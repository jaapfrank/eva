# Platform research for Eva's system choice

Checked 2026-09-27, from 12:29:27 UTC through 2026-09-27 12:35:52 UTC. Repository comparison basis supplied by coordinator: c025550b. Research only: no installation, account connection, model trial, benchmark, runtime change, or source commit. No provider-runtime spend was incurred by this investigation; research-session credit cost is unknown.

**Finding:** OpenClaw and Hermes deserve evaluation as owners of Eva's general execution lifecycle, not merely sources of channel adapters or tools. Agent Zero is a general workbench with its own lifecycle. OpenCode and Pi are reusable coding runtimes; making either the complete housemate requires more application work. None of the reviewed documentation establishes superiority over the functioning Eva 1, family-safe private recall through the actual routes, or the desired voice latency. These are architectural fit judgments, not scores.

This was a bounded official-source pass. Consequential follow-ups checked restart semantics, family trust boundaries, HA scope, Pi's new durable package, and current release metadata. Moving documentation/main branches may describe features newer than the verified stable tags. “Documented” below means the upstream documents the behavior; it does not mean it has been installed or verified for Eva. An unverified capability is not recorded as absent.

## Comparison of lifecycle ownership

| Platform | What it actually is | Documented work lifecycle | Fit for one Eva, without two competing orchestrators |
|---|---|---|---|
| **OpenClaw** | Installable personal/team assistant with a long-running Gateway owning messaging, sessions, tools and events. Hosted/local model providers and agent harnesses are replaceable plugins. [Repository](https://github.com/openclaw/openclaw), [architecture](https://docs.openclaw.ai/concepts/architecture) | Background children run in separate sessions and return results to the requester. Acceptance is distinct from completion. Persistent visible sessions support later steering. [Subagents](https://docs.openclaw.ai/tools/subagents) | **Candidate lifecycle owner.** An Eva deployment would configure/extend this owner and preserve a single task authority. Keeping Eva's current autonomous scheduler, task state and response ownership fully active around it would require explicit division of authority, not an informal wrapper. This is an architectural inference. |
| **Nous Hermes Agent** | Installable personal agent, messaging gateway and desktop/CLI product. Learning, memory, tools, providers and scheduling are part of the product. Its synchronous agent loop sits inside a gateway with background orchestration; “synchronous loop” does not mean “no concurrent conversation.” [Repository](https://github.com/NousResearch/hermes-agent), [architecture](https://hermes-agent.nousresearch.com/docs/developer-guide/architecture) | Top-level delegation returns a background handle; ordinary follow-ups keep children alive. Completion is persisted before delivery; restart of unfinished execution becomes unknown rather than automatically resumed. [Delegation](https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation) | **Candidate lifecycle owner.** Its Python/plugin boundaries may fit Eva's implementation better, but integration effort has not been measured. A wrapper that independently chooses tasks, retries, memory and final replies would reproduce much of Hermes. This is an inference, not a migration recommendation. |
| **Agent Zero** | General AI framework delivered as a Docker-based interactive Linux/browser/desktop workbench, with projects, model presets and subordinate agents. This is substantially more than a browser tool. [Repository](https://github.com/agent0ai/agent-zero) | UI supports pause/nudge and saved work; tasks can be scheduled, planned or ad hoc and inherit project context. The reviewed guide does not establish restart-safe external actions or exact cancellation/descendant semantics. [Usage](https://github.com/agent0ai/agent-zero/blob/main/docs/guides/usage.md) | **Candidate general work owner or bounded workbench.** If subordinate to Eva, use an explicit job boundary with one owner for acceptance, stop, result verification and retries. A2A connectivity alone does not settle that ownership. Whole-house channels and private identity routing remain unverified. |
| **OpenCode** | Coding-agent product with TUI, web/desktop clients and a headless HTTP server. Build/plan agents and a general subagent are documented. [Repository](https://github.com/anomalyco/opencode) | Server exposes asynchronous prompts, session status, child sessions, abort, message history, forks, todos and SSE. These are concrete integration surfaces; async HTTP does not establish durable job execution after process loss. [Server](https://opencode.ai/docs/server/) | **Good-shaped bounded coding executor.** It can own the coding session while Eva owns the household request. Selecting it as the entire housemate would require channels, social memory and initiative beyond what this pass verifies. No claim is made that extensions cannot add them. |
| **Pi / pi-mono** | Agent toolkit/harness: provider API, agent core, coding agent and composition/storage packages. The former badlogic/pi-mono URL now redirects to earendil-works/pi. [Repository](https://github.com/earendil-works/pi) | Coding sessions auto-save as a JSONL tree and support continue/fork, steering, follow-up queues, abort, SDK and stdio RPC. The coding-agent README deliberately leaves subagents and background bash to extensions/external processes. [Coding agent](https://github.com/earendil-works/pi/tree/main/packages/coding-agent) | **Composable engine, not a verified ready household product.** It can replace an agent loop cleanly if Eva retains application lifecycle responsibility. The new durable package must not be mistaken for a proven complete workflow supervisor. [Durable package](https://raw.githubusercontent.com/earendil-works/pi/main/packages/durable/README.md) |

## Memory, extensibility, channels and execution boundaries

| Platform | Memory, reusable skills, modularity | Voice, HA and private context |
|---|---|---|
| **OpenClaw** | Local state/memory; skills and plugin SDK, provider and harness substitution are documented. [Repository](https://github.com/openclaw/openclaw) | Messaging includes Telegram and WebChat; companion nodes add voice/device actions. This does **not** establish compatibility with the two installed Voice PE speakers or all HA automation editing. Critically, one Gateway is a single operator/mutually trusting team boundary: unsandboxed session tools default to visibility across the Gateway, and a session key is not authorization. Family-private memory therefore needs a verified stricter design; a separate chat alone is insufficient. [Trust model](https://docs.openclaw.ai/gateway/security/trust-model) |
| **Hermes** | Creates/refines procedural skills, searches prior sessions, and supports optional external memory. Plugins can provide tools/hooks/commands; memory and context engines are each single-select. [Repository](https://github.com/NousResearch/hermes-agent), [architecture](https://hermes-agent.nousresearch.com/docs/developer-guide/architecture) | Telegram, browser and HA are documented gateway surfaces; the platform matrix defines voice as transcription/TTS, not proof of full-duplex Voice PE. HA integration documents WebSocket state events and four REST tools, including arbitrary service calls. Automation creation/editing through Eva's general HA API is not established by that tool list. [Messaging](https://hermes-agent.nousresearch.com/docs/user-guide/messaging), [HA](https://hermes-agent.nousresearch.com/docs/user-guide/messaging/homeassistant) |
| **Agent Zero** | Projects separate files, instructions, memory, secrets and model presets. Plugin Hub, skills, custom tools, MCP and A2A are documented. Project separation must not be equated with authenticated family-person isolation. [Repository](https://github.com/agent0ai/agent-zero) | The usage guide documents local Whisper STT and Kokoro TTS plugins plus browser speech fallback. It does not prove barge-in or physical Voice PE operation. Telegram/HA ownership was not verified in this pass. [Usage](https://github.com/agent0ai/agent-zero/blob/main/docs/guides/usage.md) |
| **OpenCode** | Plugins add lifecycle hooks, custom tools and services. Local JS/TS plugins and npm plugins are supported; configured npm dependencies are installed at startup. Server APIs also expose models/providers and MCP. No person-scoped autobiographical memory was verified. [Plugins](https://opencode.ai/docs/plugins/), [server](https://opencode.ai/docs/server/) | No complete household voice/HA/Telegram route was verified. As a worker it should receive only the job's authorized context and return a result to the single household conversation owner. This is a design constraint, not an upstream defect finding. |
| **Pi** | Multi-provider API and installable packages containing extensions, skills, prompts and themes. SDK/RPC enables reuse; stock coding-agent documentation explicitly delegates MCP and subagent behavior to extensions. [Repository](https://github.com/earendil-works/pi), [coding agent](https://github.com/earendil-works/pi/tree/main/packages/coding-agent) | No full household channel/voice route was verified. Pi explicitly has no built-in filesystem/process/network/credential permission system; it runs with the launching process's authority. Isolation belongs outside the agent or in a deliberately selected extension. [Repository](https://github.com/earendil-works/pi) |

Hermes's built-in memory deserves a specific qualification. MEMORY.md and USER.md are scoped to a profile and injected as a frozen snapshot at session start. Writes persist immediately but the prompt snapshot refreshes at a new session; the documented practice is to create natural session boundaries. Session search can retrieve older conversations. This supports continuity, but it does not by itself prove a single profile can safely serve Jaap, his daughter and shared speakers, or meet Eva's no-manual-memory-maintenance requirement. External memory or profile routing may address the gap; that contract remains to be established. [Persistent memory](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)

For all five, model/provider choice is configurable in the reviewed product surface. Provider availability is not authorization to reuse subscription credentials or purchase another route. No model was selected, no provider-account connection was tested, and no latency/cost ranking is supportable.

## What restart and stop actually mean

- **OpenClaw:** each spawning session has its own child queue and concurrency budget. Children remain independent after ordinary parent completion/yield/timeout. After Gateway restart, interrupted children are finalized and the parent receives results including interruption/partial-action status; they are not blindly relaunched. Admitted queued completion handoffs persist in SQLite; direct announce attempts are best effort. Stop can report incomplete cleanup. This is a useful lifecycle contract, not proof that external effects are exactly once. [Operations](https://docs.openclaw.ai/tools/subagents/operations)
- **Hermes:** durable completion delivery and durable execution are explicitly distinguished. A completed result can be replayed after restart, but an unfinished child becomes unknown because external effects may already have happened. /stop/reset cancels the owning session's children; ordinary follow-ups do not. Gateway message guards preserve inline stop/approval handling, and routing spans platform/profile/chat keys. This supports responsive conversation at the orchestration level; actual speaker timing is unmeasured. [Delegation](https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation), [gateway internals](https://hermes-agent.nousresearch.com/docs/developer-guide/gateway-internals)
- **Pi durable:** the current public package documents records plus memory, JSONL and SQLite storage. JSONL defaults fsync off; both disk stores require one serialized writer. SQLite acknowledges process-crash survival but may lose newest commits on host/power failure. These explicit limits make it unsuitable to cite as already-proven replacement for Eva's external-action recovery merely because its name says durable. [Package README](https://raw.githubusercontent.com/earendil-works/pi/main/packages/durable/README.md)
- **Agent Zero and OpenCode:** the reviewed UI/API surfaces demonstrate stop/pause/session capabilities, not a complete crash/side-effect contract. Missing evidence remains open rather than counting as missing functionality.

A transcript, persisted task status, retryable delivery and independently verified external effect are different claims. Any selected owner needs to preserve Eva's meaningful evidence while avoiding a second planner that silently repeats the first planner's work.

## Corrections to earlier Eva research assumptions

Read in full: eva2/CONCURRENTIE_EN_HERGEBRUIK.md and eva2/evidence/reassessment/upstream-2026-09-21.json. No claim is made to have reviewed all historical evidence.

1. The August competition document's “OpenClaw channels, Hermes learning, Agent Zero computer” summary is too narrow as a present system-choice model. Current official documentation gives each a broader execution product. Treating them only as Eva's hands is an earlier architectural decision, not a demonstrated technical necessity.
2. Hermes's learning/skill advantage is supported as a documented mechanism. Its marketing exclusivity claim was not adopted, and no current comparative result proves it learns better than Eva. Its profile memory snapshot and restart-unknown execution require qualification.
3. The earlier claim that competitors have stronger voice building blocks remains plausible, but TTS/transcription/companion voice do not establish interruption and privacy on Eva's physical speakers.
4. The September metadata is now historical: OpenClaw, Hermes and Agent Zero have later verified releases. Pi's redirect/new package structure and OpenCode's server contract add relevant alternatives. Old pinned versions are not silently replaced.
5. Historical Eva strengths in result readback and crash handling are not disproved by this research. Conversely, current OpenClaw/Hermes docs explicitly distinguish interrupted execution from successful completion and avoid blindly restarting children; those concerns are not unique to Eva.
6. The earlier mandatory dependency order (Realtime/Harness/Playwright/DBOS/etc.) is not evidence that a component assembly is the best whole product. This pass does not authorize removing any functioning route or memory.

Selection remains open on five concrete questions: verified private-person routing and audible audience control; actual Voice PE/HA breadth; multi-day recovery of ambiguous effects; measured conversation quality/latency/total calls and resource use against Eva 1; and whether replacing one lifecycle genuinely removes overlapping ownership. Source support can shortlist candidates. It cannot supply the missing household comparison.
