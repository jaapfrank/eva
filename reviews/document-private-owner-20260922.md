# Private document owner across website and Telegram

Coordinator independent source review: GO for the bounded change.

The document builder supplied a shared fresh owner resolver, preserving the existing
memory-alias behaviour. Document goals retain a canonical owner while their original
source turn and task identity remain unchanged. Source reload, tool execution,
observation and document-worker recovery recheck current binding authority.
The website owner remains usable if only the Telegram link is removed. Group chats,
other principals and other installations do not gain access. Mandate and pool hashes,
existing goal data and native journals are unchanged. Other providers retain their
strict default owner authorization.

The existing binding parser moved unchanged to a permitted adapter; bootstrap keeps
its import entry point. Coordinator required this correction after finding a forbidden
provider-to-bootstrap dependency in the initial patch.

Builder evidence: 31 focused document/memory tests, then 11 focused owner/memory
checks and 2 parser-wiring checks after revisions. Coordinator independently ran the
11 relevant cases against the packaged core image: all passed in 8.65 seconds.
Core and worker candidate configuration checks also passed with the real trusted
bindings, without executing document work or calling a model.

The architecture gate still reports 30 violations. Coordinator verified every reported
file is byte-identical to HEAD before this change; no changed module is reported.
These remain release work, not a successful full architecture gate.

Installation is separate. Preserve both actual image parents, mount the existing
trusted identity file read-only for the worker, stop gracefully, start the worker before
the core, and never reset claims/journals for rollback. A metadata-only live authority
check is required after installation. This is not an owner acceptance or physical
Telegram/Voice trial.
