# Graceful publisher and Chrome shutdown

These source-only follow-ups preserve the separately reviewed dependency and security closures in `../auxiliary-runtime-20261106/`. The original 39-file recipe and its historical image proofs remain unchanged.

The two publisher patches install SIGTERM/SIGINT handlers only for the existing repeating CLI. A stop request finishes the current atomic publication and its fsync/rename, then exits normally. One-shot and owner-install modes retain their original behavior. The role-specific baseline source blobs differ; each manifest binds its own exact before/after bytes. Each overlay carries an explicit source manifest; the independently reviewed candidate preservation proof separately checks the installed distribution metadata and RECORD ownership.

The Chrome change affects MAIN only. It stops accepting, uses shutdown from a separate thread, and waits for owned request threads before exit. Existing request handlers and browser authorization are preserved. The actual proxy comes from a readonly code-file bind: copying a file into its image would be hidden. Deployment therefore binds the new root-owned, mode0444 file to the same `/proxy.py`, preserves the old source as a rollback file, and changes no data mount, route, grant or credential.

Run `python3 prepare.py --output /new/private/context --proxy-before /path/to/original/proxy.py` against the exact baseline images named in the manifests. Add `--build-images` to build the two publisher overlays. The helper verifies every recipe input, source baseline and patched result. It creates only stopped extraction containers and removes only those verified unstarted containers; it never starts a service or changes deployment configuration. It emits the reviewed Chrome code file separately. Resulting image IDs may differ across rebuilds; independently verify file ownership, configuration and source deltas before deployment.

Legacy Python PID1 processes lack the new SIGTERM handler. Their separately reviewed transition uses exactly one public Docker Stop API request with `signal=SIGINT&t=-1`, after fresh idle and generation checks. This marks a manual stop and permits no forced timeout. Do not use a new signal after an unknown result, rerun a partial installer, remove a merely created replacement, or infer graceful exit from `Running=false`; inspect the durable receipt and exact generation. The production transition and its partial receipts remain private; public evidence records the measured results without credentials or household content.
